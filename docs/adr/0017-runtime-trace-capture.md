# Runtime traces are opt-in, pseudonymized, and judge-only — never the oracle

Cortex now captures opt-in runtime traces of the agent loop for audit (issue #105), and three decisions are load-bearing. (1) PII-bearing event fields are pseudonymized at persistence via the local `rizzo-pii` sidecar before anything is stored, so neither the Cortex DB nor the API-LLM judge ever sees real PII — the alias dictionary stays on the user's machine (I1, I5). (2) A captured trace is audited by the Trajectory Judge for diagnosis + partial credit only; the pass/fail oracle remains exclusively the annotated goal state, extending ADR-0015 from eval transcripts to runtime traces (I3). (3) Capture is opt-in per session and traces are never fed back into prompts, context, training, or the learning loop — the Golden Set privacy rule (ADR-0014) extended to runtime traces (I2, I4).

## Scope boundary

The LLM-boundary PII gateway — anonymize every model call, restore responses, resolve aliases in tool arguments — is deliberately **not** part of this feature. It is tracked separately (issue #106) because it needs a pre/post-hook seam around LLM calls that Cortex does not yet have. Pseudonymizing only at trace persistence (not at the LLM boundary) was chosen because the gateway is invasive (reasoner, executor, context builder) and is itself verifiable only once trace capture exists to observe what actually reaches the models. The `messages` table keeps real conversation data — it feeds the context builder and tool execution, and never leaves the machine; only the audit artifact is pseudonymized.
